# Ye Skill Forge 2.0 改造说明

## 改造目标

让 Ye 能从模糊意图形成最小完整 Skill，沿用已有工程能力，并支持多 Skill 组合和可回滚的证据进化。借鉴 dao-skill 的根问题、资产复用和证据边界，按 Ye 自身的结构实现。

## 原有薄弱点与本次修改

| 薄弱点 | 修改 | 验证范围 |
| --- | --- | --- |
| 创建容易从功能名直接跳到模板 | 意图模型、关键问题、完整生成前准备度检查 | 字段与阻断逻辑；领域推理仍由模型执行 |
| 提问和模板之间没有连续的数据契约 | JSON 简报可由 intent 进入 create，保留根问题、边界、假设和真实触发样例 | 简报到 manifest、入口和评测样例的传递 |
| 多步骤容易被误拆成多个 Skill | 按独立触发/复用选 single、workflow 或 family | 模式选择逻辑 |
| 包级能力不足 | Router、子 Skill 注册、共享文件、handoff、路由和全包审查 | 结构、边界、样例覆盖和矛盾检测 |
| 没有拒绝、歧义和顺序路由案例 | 新增 out-of-scope、clarify、有序子 Skill 列表 | 案例契约；不计算未经执行的准确率 |
| 反馈建议没有受控落地和回滚 | proposal → preview → 显式 apply → 版本绑定回放 → 备份/rollback | 默认不写源、拒绝陈旧版本、备份恢复和后续改动保护 |
| 自身进化与子 Skill 改进混淆 | 明确两类目标，跨案例机制才上升到 Ye | 行为协议；不自动传播到安装副本或旧 Skill |
| 单 Skill 编译遗漏引用、脚本和资产 | 完整复制源资源，拒绝混合旧目标目录 | 编译文件完整性 |
| 包安装只验一个 Skill | 验证整个 Router/子 Skill 包和交接/路由 | 临时解压后的全包检查 |
| 子 Skill 默认继承元 Skill 能力和许可证 | 由作者明确给出；缺少时不编造 | 生成元数据 |
| 静态案例可能被算成发布证据 | 区分结构通过和行为验证，严格高成熟度预检保留行为缺口 | CLI 门禁与证据标记 |

主入口做了模式选择和渐进加载；不要求普通个人 Skill 执行完整发布流程。用户同时要求分析和修改时，协议要求完成文件修改，不能停在建议报告。

## 验证

```powershell
python -m unittest discover -s skills/ye-skill-forge/tests -v
python skills/ye-skill-forge/scripts/validate.py skills/ye-skill-forge --strict
python -m compileall -q skills/ye-skill-forge/core skills/ye-skill-forge/scripts
```

自动化覆盖意图传递、路径边界、路由案例、包审查、交付完整性和进化应用/回滚。这些是实现与结构证据，不是模型行为基准结果。示例包可运行 package-validate、route-eval 和 handoff-check；它尚未取得真实客户端路由或交接成功率。

截至最终复核：42 项自动化测试全部通过；Ye 严格结构校验、skill-creator 校验和 Python 编译检查通过。在临时副本中跑通简报生成、包级 IR/审查、编译、打包和安装模拟，严格发布预检按预期拒绝缺少行为证据的包。示例源目录没有保存运行报告。

## 子 Agent 最终复核

三个子 Agent 分别审查指令一致性、代码/CLI 和资源/分发。复现后修复了这些问题：

- 准备度检查先填默认语句，导致缺少边界或成功条件的简报仍可通过；现在先检查用户明确字段。
- standard 模板和触发方法复制了 Ye 专用的业务排除规则；现在以目标 Skill 的职责为准。
- 发布方法无条件要求完整门禁；现在与主入口的风险选择一致。
- Router 骨架的清单路径不明确、研究示例没有应用共享证据模式；现在明确相对路径、字段类型和交接规则。
- 编译/归档误纳入 .env、虚拟环境和编辑器状态；现在统一排除私有本地文件，保留并扫描示例配置。示例中的未引号凭据同样阻断分发，空值、明确占位符和变量引用可以保留。
- 许可信息统一维护在项目层；按用户要求移除 Skill 内重复的 LICENSE 文件，保持目录简洁。
- manifest.json 格式的多 Skill 包安装模拟只检查首个 Router；现在完整验证包，并拒绝无法识别的多入口归档。
- 触发案例错误类型导致崩溃或误判通过，输出 JSONL 只数文本行；现在解析、验证并将无效案例作为审查阻断项。

已移除没有调用者的重复摘要 `methods/intent-understanding.md`，需求建模统一在 `methods/intent.md`；其余方法文件承担不同职责，保留。清理了未使用的导入和重复过滤逻辑。用户原有 `.codex/` 未修改。

新增回归覆盖准备度一致性、私有文件分发、配置秘密阻断、manifest 包全量安装和无效评测输入。复核是代码与结构证据，不是业务输出质量基准。

## 仍需真实使用来检验的部分

- 少量问题能否准确找出不同领域用户的根问题，需要现实任务重放和用户反馈。
- CLI 不调用模型、执行通用 agent 编排或自动判断输出语义；目标 agent 负责实际工作。
- 最近资产检索是文件名关键词初筛，尚未实现语义检索和跨项目 SkillBank。
- 进化记录验证回放结构与源版本绑定；同一上下文自评不属于独立证据，局部应用默认 provisional。
- 跨平台适配仍是源文件加元数据，需要各客户端验证。严格高成熟度发布预检在缺少行为验证时会阻断。

后续改进应从真实失败案例或可靠对比证据开始；这些缺口不能靠增加文档、分数或自我宣称消除。
