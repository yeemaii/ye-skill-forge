# Ye Skill Forge 2.0 改造说明

## 2.3 改进

- 增加按需用户引导：用户只询问能力或目标不清时介绍相关入口并帮助选择；目标明确时直接工作，不重复展示菜单，也不要求先填写完整简报。
- 增加可选先例研究：默认不搜索外部同类 Skill；用户提供参考时只读指定内容，明确要求搜索时才按具体设计问题研究。研究结论允许全部舍弃，不成为创建或交付门禁。
- 加强意图审查：区分用户目标、硬约束、事实假设和实现偏好；对会妨碍结果的错误前提说明后果，同时保留知情后的可行偏好。
- 增加完整性下限与开放任务自由度：复杂任务不能仅因“第一版”省略已知必需分支；创作和开放判断只固定事实、边界与质量要求，不强加示例格式。
- 维护 Ye 时增加两层验证原则，区分 Ye 是否生成了正确资产，以及生成 Skill 在新会话中处理新输入的实际效果。
- 修复创建器始终覆盖非空 `description` 的问题；现在保留并规范化有效描述，缺失或空白时才按任务和边界生成默认描述，非字符串描述在写文件前拒绝。

验证：78 项本地单元测试通过；Ye 结构校验、静态评估、skill-creator `quick_validate.py` 和 `git diff --check` 通过；版本与界面元数据一致，Markdown 相对链接有效。新增评测案例已完成 JSON/结构校验，但它们是测试计划，不是已经执行的模型行为结果。

最终审查由三个子 Agent 分别核对指令、代码与文件用途，主 Agent 复现后修复了三处问题：默认描述将执行约束误包装为路由排除；模板生成误判或再次替换用户内容中的字面参数；统一 CLI 的 `evaluate` 在结构无效时仍返回成功。新增 6 项回归覆盖边界与近邻区分、字符串边界、字面参数保留、未知模板参数拒绝和 CLI 状态。模板形态的字面参数在结构校验中提示人工复核，实际模板中未声明的参数仍在生成时拒绝。没有发现可合理删除的源文件；新方法、示例、模板和许可证均进入分发文件集合，报告与本地状态被排除。

仍待真实使用验证：引导是否减少无效追问、可选研究是否改善具体领域方案，以及生成 Skill 在独立新会话中面对新输入时的事实和方法质量。本轮未执行独立模型或真实客户端回放，因此不把这些效果写成已证实提升。

## 改造目标

让 Ye 能从模糊意图形成最小完整 Skill，沿用已有工程能力，并支持多 Skill 组合和可回滚的证据进化。借鉴 dao-skill 的根问题、资产复用和证据边界，按 Ye 自身的结构实现。

## 2.1 改进

- 意图简报增加用户最终结果、可复用做法、材料、工具、权限和证据来源，创建不再只围绕已有失败描述。
- 新增领域方法设计说明，明确从真实材料和有效做法提炼可复用规则，并区分模板骨架与完成的领域流程。
- 新增版本绑定的行为证据入口：`behavior-evidence` 校验源摘要、评审方式和通过案例；`review` 读取证据，过期或无效证据会阻断发布。
- 未指定路径时，创建的单 Skill 和 Skill 包统一进入当前项目 `.ye/skills/`，避免把调用目录中的临时位置当作生产根。

## 2.2 改进

- 明确创建、审查、改进和维护的边界，实际子 Skill 和子 Agent 执行属于宿主；不增加 Workflow API、调度引擎或常驻进程。
- 交付目标为 Codex、Claude Code 和 generic。Codex 缺少 UI 元数据时生成最小 `agents/openai.yaml`，已有 policy/dependencies 原样保留；其他产物保留通用源语义。旧目标参数继续兼容。
- 缺少根入口的多 Skill 包生成薄 `SKILL.md`，完整保留 Router、子 Skill 与共享路径，不依赖客户端递归发现。安装计划只写到新产物，不触碰实际客户端配置。
- 默认 shell 由宿主环境决定；已有明确 shell 依赖继续保留和报告，不冒充已移植脚本。能力不足时分别交付设计、文件或工程检查结果，保留无法验证的部分。
- 加强材料到决策的提炼、语义审查及合并/删除式维护；静态标题和字段检查不替代 Agent 对具体请求的判断。
- 行为证据版本 2 绑定完整计划、环境与源摘要，保留通过、失败和未执行。记录有效与行为通过分开；失败阻断行为门禁，旧格式在高成熟度审查保留计划覆盖缺口。
- `behavior-compare` 比较外部提供的同案例、同环境记录，列出修复与退化。它只读，不调用模型或调度任务。

新增回归覆盖产物资源与策略保留、多 Skill 根入口、测试分母、失败记录、同案例退化比较和 CLI；仓库中的单 Skill 与研究包示例在三种目标完成编译、打包和临时解压校验。真实 Codex/Claude Code 发现、业务质量及人工盲审效果仍未验证，不能把本次结构回归写成跨客户端成功率或质量提升。

## 原有薄弱点与本次修改

| 薄弱点 | 修改 | 验证范围 |
| --- | --- | --- |
| 创建容易从功能名直接跳到模板 | 意图模型、关键问题、完整生成前准备度检查 | 字段与阻断逻辑；领域推理仍由模型执行 |
| 提问和模板之间没有连续的数据契约 | JSON 简报可由 intent 进入 create，保留根问题、边界、假设和真实触发样例 | 简报到 manifest、入口和评测样例的传递 |
| 多步骤容易被误拆成多个 Skill | 按独立触发/复用选 single、workflow 或 family | 模式选择逻辑 |
| 包级能力不足 | Router、子 Skill 注册、共享文件、handoff、路由和全包审查 | 结构、边界、样例覆盖和矛盾检测 |
| 没有拒绝、歧义和顺序路由案例 | 新增 out-of-scope、clarify、有序子 Skill 列表 | 案例契约；不计算未经执行的准确率 |
| 反馈建议没有受控落地和回滚 | proposal → preview → 显式 apply → 版本绑定回放 → 备份/rollback | 默认不写源、拒绝陈旧版本、备份恢复和后续改动保护 |
| 自身进化与子 Skill 改进混淆 | 明确两类目标，跨案例机制才上升到 Ye | 行为协议；不自动传播到安装副本或旧 Skill |
| 单 Skill 编译遗漏引用、脚本和资产 | 完整复制源资源，拒绝混合旧目标目录 | 编译文件完整性 |
| 包安装只验一个 Skill | 验证整个 Router/子 Skill 包和交接/路由 | 临时解压后的全包检查 |
| 子 Skill 默认继承元 Skill 能力和许可证 | 由作者明确给出；缺少时不编造 | 生成元数据 |
| 静态案例可能被算成发布证据 | 区分结构通过和行为验证，严格高成熟度预检保留行为缺口 | CLI 门禁与证据标记 |

主入口做了模式选择和渐进加载；不要求普通个人 Skill 执行完整发布流程。用户同时要求分析和修改时，协议要求完成文件修改，不能停在建议报告。

## 验证

```powershell
python -m unittest discover -s skills/ye-skill-forge/tests -v
python skills/ye-skill-forge/scripts/validate.py skills/ye-skill-forge --strict
python -m compileall -q skills/ye-skill-forge/core skills/ye-skill-forge/scripts
```

自动化覆盖意图传递、路径边界、路由案例、包审查、交付完整性和进化应用/回滚。这些是实现与结构证据，不是模型行为基准结果。示例包可运行 package-validate、route-eval 和 handoff-check；它尚未取得真实客户端路由或交接成功率。

截至最终复核：69 项自动化测试全部通过；Ye 严格结构校验、Markdown 文件预算和 Python 编译检查通过。在临时副本中跑通简报生成、包级 IR/审查、编译、打包和安装模拟；行为证据入口会拒绝过期源摘要，严格发布预检仍会拒绝缺少行为证据的 library 包。示例源目录没有保存运行报告。

## 2.2 子 Agent 复核修正

三个子 Agent 分别检查指令一致性、代码与 CLI、资源和分发；主 Agent 复现后完成修复并新增 9 项回归测试：

- 普通脚本依赖的 package.json 不再被误认成 SkillPackage；编译、审查和安装统一读取清单，manifest.json 形式的包可同时包含 npm 清单。
- 包根已有 SKILL.md 时校验其结构和包名，不能因 Router/子 Skill 正常而忽略非法入口。
- Codex 根入口优先采用根界面配置；生成原生元数据时继承 Router 的调用策略和依赖，重定位其相对图标，并保留明确 shell 前置。已有根原生文件保持原样，无需消费它的交付路径不解析它。
- 升级检查将旧平台别名归一化，名称变化不再被误报为删除平台；真实删除仍要求 major 升级。
- 进化应用接受文档声明的 client-smoke 回放方式；入口不再只要求记录通过案例，保留完整失败和未执行证据。
- 补齐 Python/PyYAML 运行前置及方法文档的按需入口，改进指令按已有授权执行，不默认停在提案。
- Ye 源仓库的分发产物携带仓库 canonical LICENSE，源 Skill 目录不新增许可证副本，用户创建的 Skill 不继承它。

未发现可合理删除的源码文件、失效相对链接或 Ye 调度业务的实现。真实客户端发现与业务效果仍未验证，本轮结论限于指令审查、实现与结构回归。

## 子 Agent 最终复核

三个子 Agent 分别审查指令一致性、代码/CLI 和资源/分发。复现后修复了这些问题：

- 准备度检查先填默认语句，导致缺少边界或成功条件的简报仍可通过；现在先检查用户明确字段。
- standard 模板和触发方法复制了 Ye 专用的业务排除规则；现在以目标 Skill 的职责为准。
- 发布方法无条件要求完整门禁；现在与主入口的风险选择一致。
- Router 骨架的清单路径不明确、研究示例没有应用共享证据模式；现在明确相对路径、字段类型和交接规则。
- 编译/归档误纳入 .env、虚拟环境和编辑器状态；现在统一排除私有本地文件，保留并扫描示例配置。示例中的未引号凭据同样阻断分发，空值、明确占位符和变量引用可以保留。
- 许可信息统一维护在项目层；按用户要求移除 Skill 内重复的 LICENSE 文件，保持目录简洁。
- manifest.json 格式的多 Skill 包安装模拟只检查首个 Router；现在完整验证包，并拒绝无法识别的多入口归档。
- 触发案例错误类型导致崩溃或误判通过，输出 JSONL 只数文本行；现在解析、验证并将无效案例作为审查阻断项。

已移除没有调用者的重复摘要 `methods/intent-understanding.md`，需求建模统一在 `methods/intent.md`；其余方法文件承担不同职责，保留。清理了未使用的导入和重复过滤逻辑。用户原有 `.codex/` 未修改。

新增回归覆盖准备度一致性、私有文件分发、配置秘密阻断、manifest 包全量安装和无效评测输入。复核是代码与结构证据，不是业务输出质量基准。

## 仍需真实使用来检验的部分

- 少量问题能否准确理解不同领域用户的结果、方法和边界，需要现实任务重放和用户反馈。
- CLI 不调用模型、执行通用 agent 编排或自动判断输出语义；目标 agent 负责实际工作。
- 最近资产检索是文件名关键词初筛，尚未实现语义检索和跨项目 SkillBank。
- 进化记录验证回放结构与源版本绑定；同一上下文自评不属于独立证据，局部应用默认 provisional。
- 跨平台适配仍是源文件加元数据，需要各客户端验证。严格高成熟度发布预检在缺少行为验证时会阻断。

后续改进应从真实失败案例或可靠对比证据开始；这些缺口不能靠增加文档、分数或自我宣称消除。
