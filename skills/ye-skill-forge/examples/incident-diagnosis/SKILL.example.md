# 故障诊断

1. 确认用户可见症状、影响范围、时间窗口、已做操作与允许的工具。区分已观察事实、用户陈述和待核实假设；不用故障开始时间的相关性证明根因。
2. 读取可用日志、指标、变更和依赖状态，保留时间及来源。关键日志缺失时选择可用替代信号并列缺口，不杜撰日志，不因一个服务日志正常排除上游或下游问题。
3. 对少量有证据的假设记录支持、反证和下一项能区分它们的检查。优先低成本、只读且有区分力的检查；检查失败或权限不足时保留未排除假设并说明下一步。
4. 根据证据提出修复或缓解，写清预期影响、回滚条件和验证办法。执行前核对当前授权范围；诊断授权不自动包含部署、删除数据或修改外部系统。
5. 若获准执行，保存操作结果并检查原用户症状、关联服务及指标。命令成功或单一健康检查恢复不能单独证明故障已解决。若未执行，交付可操作方案并标明未验证。

## 输出

按任务需要给出观察与来源、优先假设及反证、已执行检查与结果、修复/缓解方案、验证结果或计划，以及剩余风险。证据不足时可交付有依据的部分诊断；根因保持待确认，不强行输出唯一答案。

## 完成检查

- 结论能追溯到证据，检查计划能区分候选原因。
- 未执行操作和缺失证据明确，原始有效行为未因排查而破坏。
- 执行后的验证覆盖原症状与必要依赖；无法验证时停止宣称解决。
