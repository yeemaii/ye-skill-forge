# 运营与迭代

只有真实重复使用才启用遥测和漂移。事件采用本地优先、元数据最小化契约：激活、输出、脚本运行和审查结果。将 `wrong_trigger`、`bad_output`、`script_error` 和 `review_overdue` 聚合为下一轮评测或维护动作。

没有数据是 `no-data`，不是通过；数据不足时提醒而不阻塞低风险个人 skill。适应性修改先生成提案，必须经过用户授权、允许写入范围检查和回归验证；不得读取 shell history、私有日志或未明确提供的对话。

维护先读取入口、资源和已有变更，选择保留、合并、删除或更新，不默认增加规则。重复限制优先合并到唯一事实源；过期依赖、平台假设和不可达资源检查调用者后再改；规则被忽略时先查加载和路由，而不是追加相同命令。

每次说明受影响职责、调用者和要保留的行为，验证修改路径及一个原成功例。只有需要版本分发时更新版本和迁移说明；不把项目日志或维护故事塞进活动指令。纯重命名、整理等低风险修改做相应引用检查，不强制重跑无关实验。依赖或交接改变时检查实际脚本与后续阶段。
