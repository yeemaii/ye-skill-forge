# 可选先例研究

在用户希望借鉴或比较已有方案时，寻找能改善当前设计的机制。研究由宿主 Agent 使用可用的搜索、目录或源码读取能力完成；Ye 没有内置目录搜索器，也不要求安装搜索 Skill。

## 启用边界

| 用户请求 | 研究范围 |
| --- | --- |
| 没有要求研究 | 使用任务材料和当前可见资产，不自动搜索外部同类 Skill |
| 提供具体 Skill、链接或仓库 | 阅读指定参考，不自动扩展为全网调查 |
| 明确要求搜索、比较同类或借鉴外部方案 | 围绕需要解决的设计问题搜索和比较 |

用户拿不准时可以说明研究会解决什么不确定性，让其选择。选择未明确时先完成不依赖研究的需求分析。必要的领域研究、事实核查与工具文档仍按任务需要进行；同类 Skill 研究不能替代这些工作。

## 研究步骤

1. 先写清目标结果、约束及待解决的问题。需求尚不稳定时保持假设，不用先例替用户选目标。
2. 从问题形成少量查询，例如“引用完整性校验”或“复杂流程失败恢复”。来源可为官方文档、公开 Skill、代码仓库或用户资料；不强制任何目录、榜单或候选数量。
3. 先按职责和约束筛选，再阅读实际入口及必要资源。区分安装量、仓库 stars、维护、许可证和真正的行为证据；热门不意味着适合。
4. 对有影响的机制说明保留、调整、舍弃或自行设计的理由，以及将落到哪个判断、资源或验证案例。允许全部舍弃，不为完成研究而强行吸收。
5. 与需求冲突时解释差异。新证据可能促使修正方案或事实假设；有实质目标取舍时由用户选择，不能静默迁移竞品的职责、格式或工具。
6. 找到足以回答设计问题的证据时停止。无法访问来源时报告未核查部分，继续可完成工作；来源缺失不能被写成无同类方案或质量差。

只为阅读而不运行未审查的第三方脚本。直接复用代码、模板、示例或素材时核实许可证、来源和采用范围；学习机制不自动产生运行依赖。

## 交接与验证

简短说明真正读过的参考、学到的机制、采用与舍弃理由。较大研究再保存带日期和来源的报告，简单任务不增加独立文件。结论区分源码可见的设计特点、本次执行验证的结果和仍待验证的假设。

借鉴后用目标任务的正常、边界和新输入检查适用性；避免把竞品自己的测试通过当成当前 Skill 的效果证据。可参考 `keep / adapt / reject / invent` 的机制取舍方式，但不复制其品牌或必选研究流程。这一取舍方式参考 qiaomu-meta-skill，按 Ye 的可选研究与需求边界使用。
