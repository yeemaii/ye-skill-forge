# 第一性原理根因分析与局部精修

改进已有 Skill 的局部内容时，目标是用更少、更准的机制解决本质问题，而不是针对单次报错追加警告或免责补丁。日常局部修改、重构与规则清理直接按本文件执行，无需启用 `evolve` 账本或读取其他碎片方法文件。

## 第一性原理三问（先查机制，后改文字）

面对失败输出、臃肿指令或局部修改需求，先追问模型为什么会在这里偏离期望：

1. **信息流与步骤顺序是否倒置？**
   - 典型病灶：要求模型“先给结论、后列依据”或“直接输出最终状态”，导致模型为了自圆其说而脑补事实。
   - 本质修复：调整步骤顺序，建立必经的中间锚点（如“先逐条提取原文定位 -> 对齐冲突或缺失值 -> 再归纳结论”），从信息流上消除编造空间，而非追加“禁止编造事实”的口号。
2. **上下文是否存在指令冲突或注意力稀释？**
   - 典型病灶：同一职责在主入口、输出契约和引用文件中重复定义了不同措辞；或正文堆满了背景故事、角色套话和防御性声明，淹没了真正的判断条件。
   - 本质修复：合并同职责规则到唯一事实源，删掉不改变输出行为的修饰语和背景铺垫。
3. **判断标准是否缺少可分叉的条件与出口？**
   - 典型病灶：使用“深入分析、全面核对、注意准确性”等无法检验的形容词，或者未定义关键信息缺失、证据冲突时的出口。
   - 本质修复：改写为 `适用条件 -> 判断依据 -> 具体行动 -> 缺值/冲突出口`。

## 反补丁与零防御噪音三原则

| 常见劣化写法（禁止） | 第一性原理改法（采用） |
| --- | --- |
| **警告叠加**：“注意！千万不要推断未出现的日期，务必核对原文！” | **机制约束**：“相对日期仅在会议日期和时区明确时换算；否则保留原词并标注无法确定绝对日期。” |
| **免责与叠甲话术**：“本结果仅供参考，不代表最终结论，需注意潜在局限性……” | **零免责噪音**：删掉自我辩护、套话和免责声明；缺证据时直接按契约输出“未知”或具体缺口字段。 |
| **个案写死进规则**：“遇到陈某周四改下周二的情况时，以下周二为准。” | **抽象通用判断**：“同一事项存在明确撤回或更正时以最终确认为准；矛盾且未确认的归入未决问题。” |

## 局部精修四步闭环

1. **锁定最小修改面（`delete / merge / rewrite / create`）**
   - 阅读目标 Skill 的 `SKILL.md` 及实际被调用的引用文件。
   - 优先 **delete**（删除无效修饰、重复警告、免责套话）和 **merge / rewrite**（原位重写冲突或含糊段落，保持信息熵不膨胀）；只有确属缺失的稳定判断分支才 **create**。
2. **原位改写为可执行决策**
   - 保留目标 Skill 原有的有效结构、术语和正常行为。
   - 确定性、重复且手写易错的校验下沉到脚本；开放式创作与判断保留表达自由度，不强加死板章节模板。
3. **检查上下游契约一致性**
   - 若修改了输入、输出字段或触发边界，同步更新对应的 `description`、示例或子 Skill 交接契约，避免正文与示例互相打架。
4. **三类样本核对**
   - 用 **原问题输入**（确认病灶已除）、**近邻边界请求**（确认未误扩或误缩范围）和 **原成功输入**（确认已有能力未退化）推演或实跑验证。
   - 只有有基线和相同评测条件时才做量化对比；无实跑环境时如实说明推演依据与未执行项。
