# 用户引导

帮助用户找到合适的工作入口。引导是对话能力，不要求用户先学 CLI、准备完整简报或接受所有工程门禁。

## 什么时候引导

- 只调用 Ye 或问“你能做什么”：简短介绍主要入口，再问用户从哪个方向开始。
- 只有粗想法：结合已有内容推荐一个下一步，问一到两个影响设计的问题；没有明确结果时不冒充已经理解。
- 已给出目标、材料或待修复问题：直接进入相应工作，不展示欢迎菜单或重新收集已知信息。
- 询问其他能力：按问题介绍，避免把“了解功能”当成修改、安装或外部发布授权。

## 用户可选择的入口

| 用户处境 | 可说的话 | 下一步 |
| --- | --- | --- |
| 有想法或 SOP，想形成 Skill | “把这套做法做成 Skill” | 从真实输入、期望结果和有效方法开始 |
| 已有 Skill，想知道哪里不好 | “审查这个 Skill，先不修改” | 阅读目录，给具体发现和验证缺口 |
| 已有反馈，想修复或维护 | “根据这个失败改进，保留已有有效行为” | 定位根因，修改授权目标并回归 |
| 想知道是否有效或怎样交付 | “验证效果”或“适配到另一个应用” | 选择相应验证或交付路径 |
| 想参考已有方案 | “只分析这些参考”或“先研究同类 Skill” | 分别走指定参考或可选外部研究 |

初次引导通常只介绍前三到四个相关入口；用户询问全部能力时再补评测、组合、跨平台、打包、升级和回滚。可选能力只在会改变当前决策时提出，不逐项要求用户勾选。

## 示例开场

仅调用 Ye 时可以说：

> 你可以让我从想法或材料创建 Skill、审查已有 Skill、根据反馈改进，或者验证和交付。你现在是有一个想法，还是已经有 Skill 文件？

已有明确任务时可以说：

> 我先按你给出的输入和期望结果设计。当前需要确认的是负责人缺失时的处理方式，其他信息已经足够。

示例只说明引导尺度，按上下文改写。方向不清时先帮助形成可比较的目标，不把搜索同类 Skill 当成默认解决办法。用户选定路径后继续工作，不停在介绍或提案。
